# Concurrency, Cache, Export, and Accessibility Coverage

## Duplicate submissions

Ledger action creation remains the source of truth for idempotency. A
unique database constraint prevents concurrent duplicates, and serialization
retries plus winner re-read preserve one committed record. Reusing a key with
a different wallet, action type, or payload is rejected as a conflict. Retried
replays return the original receipt. Failed or expired operations remain
retryable where the existing status contract permits.

## Bounded cache invalidation and stale detection

Stale cache scans and repairs are capped at 500 entries per call. Prefix
invalidation removes matching process-memory entries and Redis tracked keys
without scanning the entire Redis keyspace. A stale entry is repaired only when
its entry type and source state support safe eviction; invalid payloads require
manual review. Dry-run repair creates no mutations. Applied repairs are
idempotent and the next read reloads from the source of truth.

Redis-only entries are not modified while Redis is offline. Callers should retry
after connectivity is restored. Unsynced indexer checkpoints are deferred rather
than overwritten.

## Privacy-safe exports

Exports use an explicit section and field allowlist. The existing `sections`
contract remains unchanged. The optional `fields` (or `fieldNames`) query
parameter filters a section to requested privacy-safe fields. Unknown fields,
unauthorized cross-wallet reads, and unauthorized field requests fail before
source records are fetched. Rows marked redacted remain excluded. Exports are
ephemeral, carry a 24-hour expiry, and are not stored server-side.

For a breaking field shape in the future, bump `EXPORT_SCHEMA_VERSION` and retain
the 1.0.0 projection until consumers migrate.

## Keyboard and async status accessibility

Modal and recovery controls preserve dialog semantics, focus management,
assertive failure announcements, polite busy/success announcements, keyboard
retry, authorization guidance, and reduced-motion behavior. Retries remain
bounded, duplicate submissions stay guarded, and disconnected or unauthorized
wallet states replace retry actions with an accessible connect action.

If a retry is exhausted, the UI disables the retry action and keeps diagnostic
information available. Dismissal restores focus to the initiating control. These
changes are additive ARIA and behavior changes with no database migration.
